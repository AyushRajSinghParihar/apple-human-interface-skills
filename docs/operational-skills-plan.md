# Operational Apple HIG topic skills

Approved scope: 158 actual topic skills; framework-agnostic examples; one installed
mega-skill plus 13 visible family routes; topic skills loaded on demand.

Preserve the published baseline a748d07 and all existing source/article/media
references. Topic procedures live at
`skills/apple-hig/subskills/apple-hig-<family>/.topics/apple-hig-<slug>/SKILL.md`.
Every exact-topic and family route enters the procedure before its source guide.

Each topic requires evidence intake, consequential topic-specific decisions,
an action procedure, a concrete deliverable, a worked transformation, observable
checks, platform/source qualifications, and conditional related-topic handoffs.
Independent reviewers reject interchangeable templates and article paraphrases.

Verification: 158 fresh artifact tasks; eight held-out stress cases repeated three
times; 13 matched published-package controls = 195 behavioral executions, excluding
grading, installation smokes and retries. Each family includes design, review and
adaptation tasks. Every topic case enters the installed root naturally; traces
must show root/family/topic/reference reads. Review all artifacts independently.
Require five 0–2 rubric axes (completion, HIG correctness, artifact usefulness,
important conditions/accessibility, evidence honesty), >=8/10, zero critical
unsupported recommendations or invented observations. Five-defect review fixtures
require all critical and >=4/5 seeded defects with no invented high-severity finding.

Freeze inputs, rubrics and case identities before rewriting instructions. Bind
records to consumed package bytes, case/prompt/fixture/rubric/harness and runtime
identity. Retain failures. Source integrity, instruction quality, actual behavior,
client discovery, and Apple-device execution are distinct verdicts.

Use authenticated Codex in copied/symlinked temporary project installations;
disable unrelated personal skills through process-only overrides. No global
installation/configuration changes. At most three agent-run evaluation workers.
Claude runtime is unverified while unauthenticated. Do not claim native SDK,
VoiceOver, rendering, physical-input or hardware verification from Linux.

Implement five pilots first: buttons, modality, accessibility, widgets, and
designing-for-visionos. Independently review/exercise each before expanding.
Rewrite README around real workflows/results, an architecture diagram, verified
installation and removal/update instructions, and separate dated evidence statuses.
Extend deterministic gates for topic ownership, routing, instruction approvals,
and behavioral evidence freshness. Publish only after required checks pass.
