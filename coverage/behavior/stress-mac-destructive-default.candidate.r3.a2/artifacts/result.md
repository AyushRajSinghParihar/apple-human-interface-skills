# macOS deletion flow review

Reviewed `interface.md` against the installed apple-hig guidance. Evidence is the supplied prose brief only; no implementation or runtime was supplied. The corrections depend on reversibility and prior intent, not button color alone.

## Concrete result and decisions

| Flow | Finding from the brief | Decision and resulting contract |
| --- | --- | --- |
| A — remove one photo | Routine removal has working Undo but always interrupts with an alert. This adds an unnecessary decision to a recoverable task. | Remove the routine confirmation. An explicit `Remove Photo` command removes only the selected photo and records one reversible operation. Keep Undo readily available; do not introduce a Return-to-delete default merely because the alert is gone. Return follows the surrounding view’s ordinary task behavior. |
| B — Empty Archive | The person explicitly requests irreversible destruction, then sees `Empty Archive?`, `Cancel`, and normal default `Empty Archive`. The destructive default is **not itself a defect** in this context. | Retain confirmation and the normal default `Empty Archive`; Return confirms the already chosen task. Keep `Cancel` alongside it, without making Cancel the default. Add a message explaining the scope and irreversibility. Cancellation returns to the prior archive state without deleting anything. |
| C — harmless inspector | Opening an inspector unexpectedly offers default `Delete All`; Return destroys unrelated data. This mismatches intent and makes ordinary keyboard use cause unexpected loss. Highest-priority correction. | Opening the inspector must only inspect and must not initiate deletion. Remove its destructive default and Return binding. If bulk deletion is needed, expose a separate explicit command with clearly bounded scope. For a warning about unexpected loss, use destructive styling and Cancel, with **no default** when deliberate reading is necessary. Return on initial presentation must not delete. |

The source generally favors nondestructive likely actions as primary, but explicitly permits a normal default in confirmation of deliberately requested destruction, such as Empty Trash. Apply that exception to B, not C. Cancel remains an available escape, not a universal replacement Return default. No-default is a considered protection for a consequential reading decision, not a rule for every deletion. See [Buttons — Role](https://developer.apple.com/design/human-interface-guidelines/buttons#Role) and [Alerts — Buttons](https://developer.apple.com/design/human-interface-guidelines/alerts#Buttons).

### Proposed copy and transitions

These are concrete product recommendations, not claims about unseen controls:

- **A:** `Remove Photo` → selected photo removed without an alert → `Undo Remove Photo` restores that same photo and its relevant state; `Redo Remove Photo` repeats removal. Use the top of the Edit menu and Command-Z / Shift-Command-Z, and visibly reveal restoration if needed. Exact restoration metadata and history persistence boundaries require product/implementation evidence. [Alerts — Best practices](https://developer.apple.com/design/human-interface-guidelines/alerts#Best-practices), [Undo and redo](https://developer.apple.com/design/human-interface-guidelines/undo-and-redo#macOS).
- **B:** title `Empty Archive?`; message `All items in the archive will be permanently deleted. This action cannot be undone.` Buttons in a horizontal row: leading `Cancel` (cancellation), trailing `Empty Archive` (normal default, Return). Show the alert only after the explicit command; delete only on confirmation. Do not add a caution symbol solely for this routine empty-archive task. The proposed “all items” scope must be checked against the real archive semantics before shipping. [Alerts — Content, Buttons, and macOS](https://developer.apple.com/design/human-interface-guidelines/alerts).
- **C:** open inspector → display inspection content with data unchanged. Keep bulk deletion outside that entry transition. If an unexpected-loss warning is still necessary elsewhere, use title `Delete All [scope]?` and message `This will delete [exact affected data]. [State verified recovery consequences.]`, replacing the brackets before release. Use leading `Cancel` and trailing destructive `Delete All`, with neither assigned default activation. Explicit activation may delete only the disclosed scope. C’s reversibility is unknown; do not copy B’s “cannot be undone” claim without evidence. If the separate command deliberately requests destruction, reassess it under B’s exception. [Alerts — Buttons](https://developer.apple.com/design/human-interface-guidelines/alerts#Buttons).

For confirmation alerts, support familiar cancellation through Cancel, Escape, and Command-Period as appropriate on Mac; every cancellation path must preserve data and return to the initiating context. Avoid stacked alerts. These are acceptance requirements, not observed behavior. [Alerts — Buttons](https://developer.apple.com/design/human-interface-guidelines/alerts#Buttons), [Keyboards — Standard keyboard shortcuts](https://developer.apple.com/design/human-interface-guidelines/keyboards#Standard-keyboard-shortcuts), [Modality — Best practices](https://developer.apple.com/design/human-interface-guidelines/modality#Best-practices).

## Acceptance checks and status

**Passed — brief-level assessment only:** A is explicitly described as undoable. B explicitly establishes prior destructive intent, irreversible consequences, named confirmation actions, and a normal Return default; that default fits the documented exception. These are supplied facts, not independently executed checks.

**Failed — current specified behavior:** A interrupts every routine undoable removal. C binds an unexpected, unrelated destructive outcome to the inspector’s default Return action. B’s supplied copy does not explicitly communicate irreversibility; the proposed message addresses that disclosure gap. B’s default does not fail this review.

**Not executed — required after implementation:**

1. A removes exactly the selected photo without confirmation. Undo restores the correct object and relevant metadata; redo repeats the same operation. Menu labels and standard shortcuts work; restoration is visible, including offscreen cases. Verify successive edits, undo followed by a new edit, and documented save/open history boundaries.
2. B appears only after explicit Empty Archive intent. Initial Return activates Empty Archive once and affects only the disclosed archive scope. Clicking Cancel, Escape, and Command-Period each dismiss without data changes. Confirm the warning accurately describes actual irreversibility.
3. C opens without changing any data. Return immediately after opening, including a repeated/held key from entry, cannot invoke deletion. If a separate warning is retained, initial Return has no default destructive effect; only deliberate activation of the named action can commit its disclosed scope. Cancel and keyboard cancellation preserve all data.
4. On a supported Mac, verify visible default treatment agrees with key behavior, keyboard-only reachability and Full Keyboard Access, focus transfer/return, and activation of deliberately focused controls separately from default Return. Verify readable enlarged labels, button separation, and no stacked alerts. Do not implement “no default” by making deletion inaccessible to intentional keyboard activation.
