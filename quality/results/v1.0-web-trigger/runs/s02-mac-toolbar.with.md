Based on your description, I’d revise the toolbar in three places:

- **Remove the custom Close button if it closes the window.** Use the standard macOS close control at the upper left. A rightmost close button introduces a competing window convention. If it finishes an editing task or dismisses temporary content, use a control appropriate to that task, such as **Done** or **Cancel**, based on its actual behavior. [Apple: Windows](https://developer.apple.com/design/human-interface-guidelines/windows)
- **Reduce and group the default actions.** Fourteen buttons aren’t automatically a violation, but they warrant a priority review. Keep frequent actions visible, group related tools, and consider customization for specialized workflows. Let the standard toolbar handle overflow as the window narrows. Apple specifies no universal maximum button count. [Apple: Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)
- **Use words wherever icons are ambiguous.** Icon-only controls are appropriate for recognizable actions; unfamiliar commands need text. Add concise hover tooltips and meaningful accessibility names to icon-only buttons. Also expose every toolbar action in the Mac menu bar so it remains available when the toolbar is hidden or customized. [Apple: Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)

This is a review of the description; icon clarity, spacing, accessibility names, and narrow-window behavior remain unverified. A screenshot and the action names would let me recommend exactly which controls to retain, label, group, or relocate.
