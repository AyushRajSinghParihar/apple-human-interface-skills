# Charting data

Source: [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/charting-data)  
Snapshot: 2026-10-25. Original implementation guidance derived from the source.

Use a chart to explain a dataset's trends, current state, or comparisons. If the job is only to supply records for searching/sorting without a visual argument, a list or table can be more suitable.

<a id="Best-practices"></a>
## Best practices

Use a chart's prominence to communicate an important insight. Keep the initial view simple and reveal subsets, detail, or richer interaction progressively. Provide both accessible descriptions of values/components and accessible interaction elements; a visual summary alone is insufficient.

<a id="Designing-effective-charts"></a>
## Designing effective charts

Prefer familiar bars or lines. Teach interpretation when a new visual language is necessary, such as introducing each metric of a ring display. Examine data at overview, group, and individual-observation levels to find useful totals, averages, subsets, and notable values. Use titles, subtitles, annotations, and a short takeaway to explain significance, while retaining accessibility labels. Match size to detail and interaction: a small snapshot can preview a larger exploratory chart. Keep comparable charts consistent, changing type/style only for meaningful differences. Across views of the same dataset, retain marks, colors, annotations, layout, and wording so overview-to-detail continuity remains obvious.

<a id="Platform-considerations"></a>
## Platform considerations

The source adds no separate rules for iOS, iPadOS, macOS, tvOS, visionOS, or watchOS.
