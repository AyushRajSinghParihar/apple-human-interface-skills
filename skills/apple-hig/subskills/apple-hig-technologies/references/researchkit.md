# ResearchKit

Source: [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/researchkit) · Retrieved 2026-10-25.

This is original application guidance based on the source text. Independent media review is recorded separately in the coverage report.

ResearchKit provides prepared screens/transitions for custom medical study participation. Clear onboarding is essential because people normally complete it only once.

<a id="Creating-the-onboarding-experience"></a>
## Creating the onboarding experience
Use the following order.

<a id="1-Introduction"></a>
### 1. Introduction
Explain study subject/purpose with a clear participation action, while allowing existing participants to sign in and resume.

<a id="2-Determine-eligibility"></a>
### 2. Determine eligibility
Check essential criteria early so ineligible people need not review consent. Use plain language and easy data entry.

<a id="3-Get-informed-consent"></a>
### 3. Get informed consent
Explain study operation/responsibility and comply with relevant ethics-board/legal/App Store requirements. Divide consent into short sections for collection, usage, risks, benefits, time, withdrawal, and other aspects, with optional deeper explanations. Let people view the whole form before agreeing. An understanding quiz can be appropriate. Follow agreement with confirmation, signature, and necessary contact information; a PDF consent copy is commonly emailed for records.

<a id="4-Request-permission-to-access-data"></a>
### 4. Request permission to access data
Then explain/request only critical device, Health, location, and other access, plus notifications if needed.

<a id="Conducting-research"></a>
## Conducting research
For surveys, state question count and estimated duration, use one question per screen, show progress, minimize length or split into shorter surveys, distinguish explanatory type from the main question, and confirm completion. Use suitable response controls for yes/no, multiple choice, dates/times, scales, and free text. For active tasks such as speech, tapping, walking, or memory, explain the action and timing/conditions clearly and make completion unambiguous.

<a id="Managing-personal-information-and-providing-encouragement"></a>
## Managing personal information and providing encouragement
Keep profile and progress dashboard accessible. Profile can edit changing health/lifestyle details, show upcoming activities, expose consent/privacy information, and let participants leave the study. A suitable dashboard can encourage continuation with daily/weekly progress, task results, or appropriate aggregate comparisons.

<a id="Platform-considerations"></a>
## Platform considerations
No extra iOS/iPadOS rules; macOS/tvOS/visionOS/watchOS are unsupported.
